AI Document Extraction & Underwriting Support System

An end-to-end AI system for a specialty commercial insurance underwriter that places hard-to-place risks. It turns a messy stream of application forms, scans, and handwritten pages into clean, validated, searchable data - and lets underwriters ask questions of that data in plain English. Everything runs fully on-premise, so no sensitive client data ever leaves the building.

The problem

Underwriting teams were spending hours re-keying data from inconsistent submissions - some clean digital forms, others scanned or handwritten, many split across multiple pages. Manual entry was slow, error-prone, and created duplicate records, and the data was too sensitive to send to cloud AI services.

How AI is used

AI handles the parts rules can't: a locally hosted vision model reads scans and handwriting, and an LLM-powered assistant translates underwriters' plain-English questions into safe SQL. Deterministic code handles everything that should be predictable.

What I built

  • AI data extraction - automatically pulls applicant details, coverage info and risk fields out of every submission, from clean PDFs to handwritten scans, so nobody has to re-type them.
  • Dual-pipeline intake - a deterministic rules parser for structured PDF forms, and a local vision model for scans and handwriting; multi-page applications are auto-merged into a single record.
  • Shared processing layer - clean, validate, de-duplicate, and load everything into one SQLite source of truth.
  • Human-in-the-loop review - underwriters approve AI extractions before commit, with fuzzy-match flags for likely duplicates and a full audit trail back to the source document.
  • "Ask AI" assistant - natural-language-to-SQL with read-only, guardrailed access so questions never modify data.
  • Privacy by design - 100% on-premise, no third-party APIs; Streamlit front end and Power BI dashboards on top.
